1. EXECUTIVE SUMMARY & SYSTEM OVERVIEW
================================================================================
Experto Store (Experto Visuals) is a modern, enterprise-ready, hyperlocal
e-commerce platform built as an interconnected monorepo-style ecosystem consisting
of four specialized applications:

1. Backend Engine (Seeder-Node): Centralized REST API, Socket.IO WebSocket
   server, MongoDB geospatial storage, Stripe webhook handler, and automated
   email dispatch engine.
2. Customer Storefront (customer-panel): High-performance customer web app
   featuring dynamic product cataloging, interactive Google Maps store discovery,
   live delivery zone calculation, Stripe Embedded Checkout, order tracking with
   live rider GPS telemetry, customer refund portal, and PWA offline capabilities.
3. Admin Management Console (admin-panel): Full-featured management dashboard
   with granular Permission-based Access Control (ACL), product catalog CRUD,
   interactive polygon map drawing for delivery zones, live order dispatching,
   and automated Stripe refunds.
4. Rider Partner Portal (rider-panel): Dedicated mobile-first console for
   delivery drivers to receive dispatches, accept orders, transition delivery
   milestones, and broadcast real-time GPS coordinates to customers and admins.

All monetary values across the entire platform are unified in Indian Rupees (INR - ₹).

4. END-TO-END WORKFLOWS & DATA FLOWS
================================================================================

--------------------------------------------------------------------------------
A. Customer Discovery, Ordering & Stripe Payment Flow
--------------------------------------------------------------------------------
1. Customer visits http://localhost:3001 and selects their delivery address.
2. The address coordinates (lat, lng) are sent to `POST /api/delivery-zones/check-serviceability`.
3. MongoDB runs a `$geoIntersects` query against the `DeliveryZone` collection.
4. If inside an active zone (e.g., Chandigarh CHD-EXP), the server returns the fee (₹30)
   and estimated delivery time (20-35 mins).
5. Customer adds items to the Cart and proceeds to `/checkout`.
6. Checkout calls `POST /api/orders/checkout`. The backend:
   - Validates live product inventory in MongoDB.
   - Calculates subtotal, delivery fee, and tax in INR.
   - Creates a pending `Order` document.
   - Generates a Stripe Checkout Session via the Stripe Node SDK.
   - Returns the Stripe `clientSecret` and redirect URL.
7. Customer completes payment on Stripe.
8. Stripe sends a signed `checkout.session.completed` event to `POST /api/stripe/webhook`.
9. The webhook controller validates the Stripe cryptographic signature using the raw body,
   marks the order as `paymentStatus: 'paid'`, decrements product stock, emits a
   `payment:success` Socket.IO event, and triggers an order confirmation email via Nodemailer.

--------------------------------------------------------------------------------
B. Hyperlocal Geospatial Delivery Serviceability Flow
--------------------------------------------------------------------------------
1. Delivery zones are stored as GeoJSON `Polygon` objects with 2dsphere indexes:
   `coordinates: [[[lng1, lat1], [lng2, lat2], [lng3, lat3], [lng1, lat1]]]`
2. When customer inputs an address (via browser Geolocation or OpenStreetMap search):
   - Backend performs: `location: { $geoIntersects: { $geometry: { type: "Point", coordinates: [lng, lat] } } }`
3. If an intersecting zone has `isActive: true`, serviceability is granted.
4. If outside, the UI marks the order as "Outside Delivery Zone" and prevents checkout
   for items requiring hyperlocal courier dispatch.

--------------------------------------------------------------------------------
C. Real-Time Telemetry & Socket.IO Communication Flow
--------------------------------------------------------------------------------
1. Socket server runs on port 5000 (`/socket.io`).
2. Clients authenticate via JWT handshake (`auth: { token }`).
3. Socket service maintains room namespaces:
   - `order_<orderId>`: Customer, Admin, and Rider join this room for private telemetry.
   - Global broadcasts: `product:stockUpdated` (updates catalog counters in real time).
4. Any state mutation in the database immediately triggers a Socket broadcast:
   - Stock update -> `io.emit('product:stockUpdated', { productId, stock })`
   - Order status -> `io.to('order_' + id).emit('order:statusUpdated', order)`
   - Payment confirmed -> `io.to('order_' + id).emit('payment:success', data)`
   - Rider coordinates -> `io.to('order_' + id).emit('delivery:location', coords)`

--------------------------------------------------------------------------------
D. Rider Dispatch & Live GPS Tracking Flow
--------------------------------------------------------------------------------
1. Admin opens `/orders` in `admin-panel` and clicks "Assign Rider" on a paid order.
2. Backend updates `deliveryStatus: 'assigned'` and emits `delivery:assigned` via Socket.
3. Rider receives the order alert in `rider-panel` (http://localhost:3002).
4. Rider accepts the delivery and marks "Picked Up".
5. When Rider clicks "Start Delivery" (`on_the_way`):
   - The rider's browser starts streaming GPS coordinates (`navigator.geolocation.watchPosition`
     or simulated path) to `socket.emit('rider:location', { orderId, latitude, longitude })`.
6. Customer watching `/orders/[id]/track` in `customer-panel` receives `delivery:location`
   and the Google Map smoothly animates the rider's scooter icon along the route.
7. Rider marks "Delivered": order status updates to `delivered`, customer receives completion
   alert, and delivery timestamp is recorded.

--------------------------------------------------------------------------------
E. Customer Refund Request & Admin Automated Stripe Processing Flow
--------------------------------------------------------------------------------
1. Customer visits `/orders` on `customer-panel` and clicks "Request Refund" on any delivered order.
2. Customer selects a reason (e.g., defective, wrong item, late) and inputs notes.
3. Frontend sends `POST /api/orders/my-refund-requests`.
4. Backend creates a `RefundRequest` document linked to the Order, sets `refundStatus: 'requested'`,
   and notifies administrators via email and Socket.IO.
5. Admin opens `/refunds` in `admin-panel`.
6. Admin clicks "Approve & Refund via Stripe":
   - Backend calls Stripe API: `stripe.refunds.create({ payment_intent: order.stripePaymentIntentId, amount })`.
   - On Stripe success, Order is updated to `refundStatus: 'refunded'`.
   - RefundRequest is updated to `status: 'refunded'`.
   - An email receipt with the Stripe Refund ID is sent to the customer.
   - A live Socket alert updates the customer's screen instantly.

--------------------------------------------------------------------------------
F. Granular Role-Based Access Control (RBAC / ACL) Flow
--------------------------------------------------------------------------------
1. Roles (Admin, Staff, Rider, Customer) have arrays of `Permission` references.
2. Permissions follow `resource:action` convention (e.g., `products:create`, `refunds:read`).
3. On login, JWT token is signed with the user ID, email, and role.
4. Backend middleware `authMiddleware.js`:
   - `protect`: Decodes JWT, verifies signature, and attaches `req.user`.
   - `requirePermission('products:create')`: Fetches user's role and verifies whether the
     role possesses the required permission. If not, returns `403 Forbidden`.
5. Frontend panels check permissions to conditionally render navigation links and action buttons.

--------------------------------------------------------------------------------
G. Progressive Web App (PWA) Offline & Caching Flow
--------------------------------------------------------------------------------
1. `customer-panel` provides a fully compliant Progressive Web App.
2. Web App Manifest (`app/manifest.ts`) defines icons, dark theme color (`#4f46e5`),
   display mode (`standalone`), and app metadata.
3. Service Worker (`public/sw.js` v2):
   - Precaches offline fallback page (`/offline`) and branding icons.
   - Bypasses localhost development, Next.js internal chunks, Socket.IO, and Stripe APIs.
   - Provides Network-First navigation with instant offline fallback screen when network drops.
4. `PWAContext.tsx` handles `beforeinstallprompt`, provides custom "Install App" banners,
   and purges legacy caches automatically.

6. DATABASE SCHEMAS & MONGOOSE MODELS
================================================================================

1. User
   - name: String
   - email: String (unique)
   - password: String (bcrypt hash)
   - phone: String
   - role: ObjectId -> Role
   - isActive: Boolean
   - timestamps: true

2. Role
   - name: String (unique: Admin, Staff, Rider, Customer)
   - permissions: [ObjectId -> Permission]
   - description: String

3. Permission
   - name: String
   - code: String (unique: e.g. dashboard:read, products:create, refunds:process)
   - description: String

4. Product
   - title: String
   - description: String
   - price: Number (INR)
   - category: String
   - quantity: Number (inventory count)
   - images: [String] (upload paths)
   - isDeliverable: Boolean
   - timestamps: true

5. DeliveryZone
   - name: String
   - code: String (unique: e.g. CHD-EXP, MOH-URB, PKL-EXP, GTR-TRI)
   - deliveryFee: Number (INR)
   - estimatedDeliveryTime: String (e.g. "20-35 mins")
   - minOrderAmount: Number (INR)
   - isActive: Boolean
   - location: {
       type: "Polygon",
       coordinates: [[[Number, Number]]]  // GeoJSON [lng, lat]
     } (2dsphere index)

6. Order
   - customer: ObjectId -> User
   - items: [{ product: ObjectId, title: String, price: Number, quantity: Number }]
   - shippingAddress: { address: String, city: String, state: String, lat: Number, lng: Number }
   - deliveryZone: ObjectId -> DeliveryZone
   - deliveryFee: Number
   - tax: Number
   - totalAmount: Number
   - orderStatus: String ('pending', 'confirmed', 'processing', 'delivered', 'cancelled')
   - paymentStatus: String ('pending', 'paid', 'failed', 'refunded')
   - deliveryStatus: String ('unassigned', 'assigned', 'accepted', 'picked_up', 'on_the_way', 'delivered')
   - assignedRider: ObjectId -> User
   - stripeSessionId: String
   - stripePaymentIntentId: String

7. RefundRequest
   - order: ObjectId -> Order
   - customer: ObjectId -> User
   - amount: Number
   - reason: String
   - customerNote: String
   - adminNote: String
   - status: String ('requested', 'approved', 'rejected', 'refunded')
   - stripeRefundId: String

7. SOCKET.IO REAL-TIME EVENT REFERENCE
================================================================================

A. Client to Server:
- `join:order` (data: { orderId }): Joins private order room `order_<orderId>`.
- `leave:order` (data: { orderId }): Leaves order room.
- `rider:location` (data: { orderId, latitude, longitude, heading, speed }):
  Broadcasts rider GPS telemetry.

B. Server to Client:
- `order:statusUpdated` (payload: { orderId, orderStatus, paymentStatus, deliveryStatus })
- `delivery:assigned` (payload: { orderId, riderId, riderName, deliveryStatus })
- `delivery:status` (payload: { orderId, status, riderId, riderName })
- `delivery:location` (payload: { orderId, latitude, longitude, timestamp })
- `payment:success` (payload: { orderId, paymentStatus, totalAmount })
- `payment:failed` (payload: { orderId, failureReason })
- `refund:statusUpdated` (payload: { refundRequestId, orderId, status, approvedAmount })
- `product:stockUpdated` (payload: { productId, stock })
- `notification:new` (payload: { title, message, type })

9. STEP-BY-STEP OPERATION & USER GUIDE
================================================================================

1. Running the Platform:
   - Backend Server: cd Seeder-Node && npm run dev (Port 5000)
   - Admin Panel:    cd admin-panel && npm run dev (Port 3000)
   - Customer Panel: cd customer-panel && npm run dev (Port 3001)
   - Rider Panel:    cd rider-panel && npm run dev (Port 3002)

2. Testing the Full Lifecycle:
   Step 1: Open Customer Panel (http://localhost:3001). Choose delivery location
           (e.g., Sector 17, Chandigarh). Add a product to cart and checkout.
   Step 2: Complete the Stripe payment. You will see payment success and order confirmed.
   Step 3: Open Admin Panel (http://localhost:3000, Login: admin@experto.com).
           Navigate to "Orders & Tracking", find the paid order, and click "Assign Rider".
   Step 4: Open Rider Panel (http://localhost:3002, Login: rider@experto.com).
           Accept the order and click "Start Delivery". The rider starts broadcasting GPS.
   Step 5: Switch back to Customer Panel -> "My Orders" -> "Track Delivery".
           Watch the rider icon move live on the Google Map in real time!
   Step 6: In Rider Panel, click "Mark Delivered". Order completes.
   Step 7: In Customer Panel, click "Request Refund" on the order. Enter reason.
   Step 8: In Admin Panel -> "Refund Requests", review and click "Approve & Refund via Stripe".
           Stripe processes the refund, and confirmation emails are sent automatically!
